# O30 Feature Guide

O30 uses CAN FD and has 20 joints. Examples use `/linkerbot_hand`; replace it with the actual driver path for multiple hands. Commands move the device: check current state, direction and targets first.

## Connect the device

```bash
ros2 launch linkerbot_hand_ros hand.launch.py \
  model:=o30 side:=right \
  transport_json:='{"backend":"socketcan","channel":"can0"}'
```

[Automatic connection](discovery.md) identifies the model for you. Set side to the actual left or right hand.

## Identity and capabilities

```bash
ros2 topic echo --once --qos-durability transient_local /linkerbot_hand/capabilities
ros2 service call /linkerbot_hand/get_device_info \
  linkerbot_hand_msgs/srv/GetDeviceInfo '{timeout_s: 0.2}'
ros2 topic echo --once --qos-reliability best_effort /linkerbot_hand/state/angles
```

Check `identity.verified=true`, then inspect supported commands, ranges, tactile fields and configuration read modes.

## Angle control

Angle state contains `raw`, `percent` and optional `physical_rad`. Check `meta.valid`, `meta.stale` and per-axis validity before use. Flexion percent uses 0 for flexed and 100 for extended; directional joints follow capability endpoint labels.

```bash
ros2 run linkerbot_hand_ros angle_command --values 50 50 50 50 50 50 50 50 50 50 50 50 50 50 50 50 50 50 50 50
```

`angle_command` uses percent by default; add `--raw` for protocol values. The Python client offers `set_percent_angles(values)` and `set_angles(raw_values)`. Protocol completion does not prove mechanical arrival; see [control examples](examples.md).

## Speed settings

Use `HandCommandClient.set_speeds(raw_values)` or `command/speeds` with one value per joint. Raw values are protocol counts. `configured_speeds` is a setting; `measured_speeds` is live feedback. See model details below for configuration readback. Models without `get_configured_speeds` do not expose that ROS read service.

```python
# hand is a persistent HandCommandClient on a spinning node.
publication = hand.set_speeds([100] * len(hand.joint_names))
```

```bash
ros2 service call /linkerbot_hand/get_configured_speeds \
  linkerbot_hand_msgs/srv/GetRawValues '{timeout_s: 0.5}'
```

## Acceleration settings

Use `HandCommandClient.set_accelerations(raw_values)` or `command/accelerations`. Read raw ranges from `capabilities.commands`.

## State and tactile reads

```bash
ros2 param set /linkerbot_hand current_hz 10.0
ros2 param set /linkerbot_hand temperature_hz 1.0
ros2 topic echo --once --qos-reliability best_effort /linkerbot_hand/state/currents
```

Enable other supported state channels through [parameters](configuration.md). Request fn tactile data and read a complete sample:

```bash
ros2 param set /linkerbot_hand force_fn_hz 10.0
ros2 topic echo --once --qos-reliability best_effort /linkerbot_hand/state/force_fn
```

For O30, first check `force_fields.support_known/supported` and request only fields supported by installed sensors. Full descriptors use `state/tactile_sensors`. Fields, units and validity are described in [tactile data](force.md).


## Torque limits and motion times

`HandCommandClient.set_torques_limits(raw_values)` sets torque limits; `set_motion_times(raw_values)` sets motion times. Both take 20 raw values; units and ranges follow capabilities. These differ from current limits and measured torque.

```bash
ros2 service call /linkerbot_hand/get_torques_limits \
  linkerbot_hand_msgs/srv/GetRawValues '{timeout_s: 0.5}'
ros2 service call /linkerbot_hand/get_motion_times \
  linkerbot_hand_msgs/srv/GetRawValues '{timeout_s: 0.5}'
ros2 param set /linkerbot_hand torques_hz 10.0
ros2 topic echo --once --qos-reliability best_effort /linkerbot_hand/state/torques
```

## Model details and management

Twenty-joint CAN FD hand. Supports angles, speeds, accelerations, current limits, torque limits and
motion times, with queryable settings. Live current, measured torque and voltage can be polled.
Stall reads and settings are supported.

`current_limits` and `torques_limits` are distinct settings. `torques_hz` polls measured torque;
it does not make `command/torques` available. Read `returns_current_state` to determine angle-write feedback support.

Tactile support follows the actual descriptor. Check `force_fields.support_known/supported` before
selecting fn/fns/ft/fts/fd/fds/px. TASHAN_GATHER exposes one fn/ft/fd/px value per fingertip;
without FnS it publishes no five-finger normal resultant. See [tactile fields](force.md).

Stop application commands, then [deactivate and cleanup](configuration.md#lifecycle) to close the connection.
